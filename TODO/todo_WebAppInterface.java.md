# План портирования WebAppInterface.java (фикс автобоя и верхнего фрейма)

## 1. Назначение файла
WebAppInterface.java — мост между JS в WebView и Android-логикой. Для автобоя он должен повторять поведение C# ScriptManager.AutoBoi()/FormMain.AutoBoi() по переключению состояния и запуску обновления верхнего фрейма.

## 2. Проблема в текущем Android-порте
- Кнопка AutoBoi() переключала только AppVars.Autoboi.
- Флаг профиля AppVars.Profile.LezDoAutoboi не синхронизировался.
- MainPhp.mainPhpFight() использует именно LezDoAutoboi для ветвления логики, из-за чего после ручного стопа автобоя возникало рассогласование.
- В результате верхний фрейм после остановки автобоя мог не восстанавливаться так же, как в C#.

## 3. Решение для Android
- В AutoBoi() синхронизировать оба состояния:
  - AppVars.Autoboi
  - AppVars.Profile.LezDoAutoboi
- Сохранять профиль через AppVars.Profile.save(context) после переключения.
- При включении автобоя инициировать reload main.php?get_id=56&act=10&go=inf (аналог C# ReloadMainPhpInvoke).

## 4. План реализации
- [x] Обновить AutoBoi() в WebAppInterface.java.
- [x] Добавить запись в профиль LezDoAutoboi=true/false.
- [x] Добавить сохранение профиля.
- [x] Добавить принудительный reload верхнего фрейма при включении автобоя.
- [x] Проверить сборкой :app:compileDebugJavaWithJavac.

## 5. Критерии готовности
- После нажатия кнопки автобоя состояния Autoboi и LezDoAutoboi не расходятся.
- При выключении автобоя верхний фрейм продолжает отрисовываться штатно.
- При включении автобоя выполняется обновление боевой страницы и цикл продолжается.
