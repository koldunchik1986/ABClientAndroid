## 🔴 MainPhp.java — КРИТИЧНЫЙ РЕФАКТОРИНГ

### Почему это критично?

1. **Нарушает Rule 6:** Содержит бой, инвентарь, быстрые действия, капчу, парсинг
2. **Невозможно тестировать:** 6200+ строк в одном файле
3. **Трудно отламывать:** изменение в боевой логике может сломать инвентарь
4. **Риск VCode ошибок:** 40+ методов могут неправильно работать с VCode
5. **Нарушает Event-Driven:** нельзя быстро отследить где задержка

### Распределение ответственности (текущее):

```
MainPhp (6229 строк) = 100%
├─ Боевая логика: ~24% (1500 строк)
├─ Инвентарь: ~14% (900 строк)
├─ Быстрые действия: ~13% (800 строк)
├─ Утилиты парсинга: ~5% (300 строк)
├─ Капча: ~6% (400 строк)
├─ Bridge'ы: ~6% (400 строк)
└─ Остаток/дедуп: ~32% (2000 строк)
```

### Распределение после рефакторинга (идеал):

```
MainPhp (1000 строк) → координация + entry-points
FightProcessor (1500 строк) → вся боевая логика
InventoryProcessor (900 строк) → инвентарь + быстрые действия
CaptchaHandler (400 строк) → парсинг и диалоги капчи
UrlParseUtils (200 строк) → утилиты URL/JS
HtmlGenerationUtils (300 строк) → построение HTML
```
