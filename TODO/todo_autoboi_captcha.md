# Автобой и капча при завершении боя

## Наблюдения из логов (Android)
- `Logs/logcat_runtime_20260227_22.txt`: после победы с включённым автобоем многократно дергается `main.php?get_id=61&act=7&fexp=142...` без завершения боя. Сервер отвечает 200, но верхний фрейм остаётся, бой не закрывается.
- В ответах сервер не принимает наш запрос и повторно возвращает страницу завершения → вероятно, требовалась капча, а мы отправляем GET без параметра `code` (или без ввода пользователем).

## Что делает ПК-версия C# (эталон)
- В `ABClient/PostFilter/MainPhp.cs` (ветка завершения боя):
  - При `fight_ty[4] == 2` (бой завершён) и наличии `fexp[4]` строится форма `FEND` с `<img src="/modules/code/code.php?{fexp[4]}">` и `<input name=code size=4>`.
  - Параметры, которые отправляются вместе с кодом: `get_id=61`, `act=7`, `fexp`, `fres`, `vcode`, `min1`, `max1`, `min2`, `max2`, `sum1`, `sum2`, `ftype`, `code`. Для авторежима нужна ручная капча.
  - Если `fexp[6] != 0`, капча не требуется — кнопка «Завершить бой» без поля ввода.
- Итог: ПК-клиент **не пытается** автокликать при требуемой капче: он показывает форму и ждёт ввода пользователя.

## Текущее поведение Android
- Автобой сразу редиректит на `get_id=61&act=7...` без проверки наличия капчи и зацикливается, не отображая форму. Пользователь не может ввести код.

## Гипотеза причины
- Мы не разбираем `fexp[4]/fexp[6]` и не ищем форму `FEND`. При наличии капчи нужно отменить автозавершение, показать страницу/диалог с картинкой и полем ввода, затем отправить `code` вместе с параметрами боя.

## План реализации (Android)
- [ ] В `LezFight`/`MainPhpFight` при разборе завершения боя сохранять признаки капчи (`needCaptcha = fexp[4] not empty && fexp[6]==0`).
- [ ] Если `needCaptcha`: 
  - останавливать автобой (`Autoboi = Timeout/Off`), очищать `FightLink`, показывать пользователю фрейм/диалог с изображением капчи (`/modules/code/code.php?{fexp[4]}`) и полем ввода.
  - При вводе кода формировать GET `main.php?get_id=61&act=7&...&code=XXXX` (аналог формы `FEND`) и загрузить во фрейм.
- [ ] Если капчи нет (`fexp[6]!=0` или `fexp[4] пуст`), можно автокликать как сейчас.
- [ ] Добавить логирование: обнаружена капча, ссылка на картинку, результат отправки кода.
- [ ] Регресс: убедиться, что при выключенном автобое бой завершает пользователь вручную (форма остаётся доступной).
