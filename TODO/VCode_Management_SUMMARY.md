ПРИМЕР: Автоматическая рыбалка

1. ИНИЦИАЦИЯ
   ↓
   User clicks "Start Fishing"
   AutoFishing enabled = true

2. ЗАПРОС НА РЫБАЛКУ  
   ↓
   browser.navigate("main.php?get_id=55")

3. ПОЛУЧЕНИЕ ОТВЕТА
   ↓
   HTML Response от сервера с:
   - <input type=hidden name=vcode value="26ed9c9afae6128894a60e1b8275ebf4">

   → Вызыв MainPhp()
   → Определение: есть рыбалка
   → Вызов MainPhpFish()

   var vcode = SubString(html, "=vcode value=", ">");

   if (string.IsNullOrEmpty(vcode))

6. ПОЛУЧЕНИЕ ДРУГИХ ПАРАМЕТРОВ

   VCode = ss[0]

## 📊 ТАБЛИЦА СРАВНЕНИЯ: C# ↔ Android

| Характеристика | C# версия | Android |
|---|---|---|
| **Главная точка обработки** | `Filter.Process()` | `GameResponseHandler` |
| **Хранилище VCode** | Распределённое (локальные переменные) | Распределённое (локальные переменные) |
| **Жизненный цикл VCode** | Только в методе парсинга | Только в методе парсинга |
| **Кэширование** | Минимально (ParsedDressed) | Не использовать |
| **Валидация** | `if (string.IsNullOrEmpty())` | `if (vcode == null \|\| empty)` |
| **Использование** | Немедленно в том же методе | Немедленно в том же методе |
| **Синхронизация** | Через Filter.Process() | Через GameResponseHandler |
| **Передача между модулями** | Через ссылки/формы | Через ссылки/навигацию |
| **Ошибка "неверный VCode"** | Валидация перед использованием | Валидация перед использованием |

## 🎯 КЛЮЧЕВЫЕ ВЫВОДЫ

### Что НА САМОМ ДЕЛЕ происходит в C# версии:

```
1. VCode - это НЕ переменная состояния приложения
   └─ Это переменная СЕАНСА сервера
   └─ Меняется с каждым запросом
   └─ Должна быть актуальной в момент использования

2. Система НЕ хранит VCode централизованно
   └─ Парсит из каждого ответа
   └─ Использует немедленно
   └─ Не сохраняет "на потом"

3. Каждый модуль работает с СОБСТВЕННЫМ VCode
   └─ Рыбалка имеет VCode рыбалки
   └─ Бой имеет VCode боя
   └─ Они НЕ совместимы

4. Синхронизация через Filter.Process()
   └─ Единая точка обработки
   └─ Последовательное распределение
   └─ Нет гонки между потоками

5. Валидация - главная защита
   └─ Если VCode нет → отмена действия
   └─ Если VCode старый → ошибка сервера
   └─ Система обходит это, используя свежий VCode
```

### Для Android портирования:

```
✅ REPLICATЕ:
   1. Распределённое хранилище VCode
   2. Парсинг "на лету"
   3. Единая точка обработки ответов
   4. Валидация перед использованием
   5. Немедленное использование

❌ AVOID:
   1. Централизованное хранилище VCode
   2. Долгосрочный кэш VCode
   3. Отложенное использование VCode
   4. Передача VCode между модулями
   5. Использование VCode без валидации
```
