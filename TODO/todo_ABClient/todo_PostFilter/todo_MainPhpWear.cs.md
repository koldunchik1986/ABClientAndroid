## 1) План портирования `MainPhpWear.cs`

`ABClient/PostFilter/MainPhpWear.cs` — это центральный модуль авто-надевания предметов (рыбалка/охота) и чтения результата разделки.

Для текущей задачи приоритет — ветка авто-охоты (`MainPhpArmedKinfe`, `MainPhpWearKnife`, `MainPhpGetSkinRes`) с привязкой к `AUTO_SKIN`.

## 2) Функциональность в C# (детально)

### 2.1 `MainPhpWearUd(html)` / `MainPhpIsMustWearUd(html)` (рыбалка)
- Использует `ParsedDressed` и `GetInvList`.
- Проверяет, надеты ли удочки из профиля.
- Если нет — ищет `WearLink` в инвентаре и делает `BuildRedirect(...)`.
- При конфликте слота может сначала снять предмет (`get_id=57&uid=...&s=0&vcode=...`).
- Если нужная удочка отсутствует — останавливает авто-рыбалку.

- **`GetInvList(html)`**: Вспомогательная функция, которая парсит инвентарь и возвращает список объектов `InvEntry`.
> Эта часть нужна как архитектурный шаблон для авто-охоты, даже если сейчас фокус на ноже.

- **`MainPhpIsMustWearUd(html)`**: Проверяет, должен ли пользователь надеть удочку согласно настройкам.
### 2.2 `GetInvList(html)`
- Идет по HTML-строкам инвентаря и создает список `InvEntry`.
- Используется всеми ветками wear-логики (удочки и нож).

- **`MainPhpWearKnife(html)`** и **`MainPhpArmedKinfe(html)`**: Логика для автоматического надевания разделочного ножа. Одна функция проверяет, надет ли нож, другая - находит и надевает его из инвентаря.
### 2.3 `MainPhpArmedKinfe(html)` (проверка ножа)
- Создает `ParsedDressed`.
- Возвращает `parsedDressed.IsWearKnife()`.
- По сути это «датчик состояния»: нож уже надет или нет.

- **`MainPhpGetSkinRes(html)`**: Парсит страницу с результатами разделки, извлекает полученные ресурсы, сравнивает с предыдущими значениями и выводит отчет в чат.
### 2.4 `MainPhpWearKnife(html)` (надевание ножа)
- Опирается на тот же список допустимых ножей, что и `IsWearKnife`.
- Если нож не надет:
  - парсит `GetInvList(html)`,
  - ищет первый подходящий нож с `WearLink`,
  - отдает `BuildRedirect("Одеваем ...", wearLink)`.
- Если нож не найден — сбрасывает `AppVars.AutoSkinArmedKnife = false`.

### 2.5 `MainPhpGetSkinRes(html)` (результаты разделки)
- Ищет блок ресурсов (таблица после маркера `<B>Рост</B>`).
- Для каждой строки ресурса парсит:
  - название ресурса,
  - вес/количество (double).
- Сравнивает с предыдущим значением в `AppVars.SkinRes`:
  - показывает текущий объем;
  - если есть прирост — показывает `(+diff)`.
- Формирует чат-сообщение `Охотничьи ресурсы: ...`.

## 3) Реальная оркестрация в C# (`MainPhp.cs`)

`MainPhpWear.cs` вызывается не напрямую из UI, а через флаги в `MainPhp.cs`:
- `AutoSkinCheckUm` → переход на страницу умений;
- `AutoSkinCheckRes` → переход в инвентарь `&im=5` и вызов `MainPhpGetSkinRes`;
- `AutoSkinCheckKnife` → проверка надетого ножа;
- `!AutoSkinArmedKnife` → переход в `&im=0&wca=4` и вызов `MainPhpWearKnife`.

1.  **Создать класс `EquipmentManager` в Android:**
    - Будет отвечать за проверку и смену экипировки для различных задач (рыбалка, разделка).
2.  **Создать класс `DressedStateParser`:**
    - Аналог `ParsedDressed`. Будет парсить HTML и предоставлять информацию о том, что в данный момент надето на персонаже.
3.  **Интеграция с `AutoFishManager` и `AutoSkinManager`:**
    - Перед началом рыбалки `AutoFishManager` должен обратиться к `EquipmentManager`.
    - `EquipmentManager` проверит, надеты ли удочки. Если нет, он должен инициировать серию `WebView`-запросов для их надевания (сначала снять мешающие предметы, затем надеть нужные).
    - Аналогичная логика должна быть для `AutoSkinManager` и ножа.
4.  **Парсинг ресурсов:**
    - Логику из `MainPhpGetSkinRes` следует перенести в `AutoSkinManager` для анализа результатов разделки.
Это обязательная часть 1:1-порта, иначе `MainPhpWear` не работает в живом цикле.
