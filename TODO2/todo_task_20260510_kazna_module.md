# Задача 2026-05-10: модуль Казна

## Предварительное описание

Нужно реализовать отдельный Android-модуль `Казна` в `app2/ANClient`, который заменит пункт бокового меню `Инвентарь` и будет работать как быстрый поиск предметов клановой казны.

## Исходные данные пользователя

- Основной запрос казны: `main.php?useaction=clan-action&addid=3`.
- Трафик полного ответа: `kazna.har`.
- Примеры ожидаемых списков: `kazna_vse.txt`, `kazna_arts.txt`, `kazna_rars.txt`.
- Трафик взятия предмета: `kazna_take.har`.
- Начальное требование: кэш результата парсинга сохранять рядом с `clans.txt`; фактическая реализация после profile-scoped доработки хранит файлы в `info/<profile nick>/kazna/`.

## Предварительные правила фильтрации

- `[ ]` Вкладка `Все`: все предметы казны из ответа сервера.
- `[ ]` Вкладка `Арты`: предметы, у которых при парсинге найден коэффициент артефакта, например `1.19`.
- `[ ]` Вкладка `Рары`: предметы без коэффициента артефакта, у которых максимальная долговечность `>= 300`, например `100/300`, `100/1000`.
- `[ ]` Вкладка `Обычные`: предметы без коэффициента артефакта, у которых максимальная долговечность `< 300`.

## Результаты анализа HAR/HTML

- Основной список казны в HAR был получен через `http://neverlands.ru/main.php?useaction=clan-action&addid=3`, но для гарантированного сброса серверного `wca` Android использует reset-URL ПК-версии `http://neverlands.ru/main.php?wfo=1&useaction=clan-action&addid=3`.
- Серверная категория задаётся параметром `wca`, например `main.php?wca=4&useaction=clan-action&addid=3`.
- Ссылки категорий находятся в блоке `<td colspan=5>` и содержат иконки `image.neverlands.ru/gameplay/invent/cat/*.gif` или близкие серверные иконки для специальных категорий.

- Строка предмета имеет 5 ячеек: название, текущая отметка `В-инвентаре`/кто положил, долговечность, статус, действие. Это не владелец вещи; реальный `Владелец:` приходит только из блока свойств inventory-card.

- Кнопка `Пожертвовать` использует `main.php?get_id=18&vcode=...&uid=...&clan=...&wpr=...&wcs=...&wms=...&useaction=clan-action&addid=3&wn=...`.
- У занятых предметов сервер часто не отдаёт action-link и отдельный `uid`; такие строки сохраняются в списке для видимости, но действия и добавление в комплект доступны только при наличии `uid` из action-link.
- Артефакт определяется по коэффициенту вида `1.19` в первой ячейке строки.
- Рар определяется как предмет без коэффициента арта и с максимальной долговечностью `>= 300`.
- Обычный предмет определяется как предмет без коэффициента арта и с максимальной долговечностью `< 300`.
